# もみかるFC 月次レポート自動化（フェーズ1）

見崎さんがアップしたレポートを、各加盟店 Drive フォルダへ**コピー**し、オーナーに閲覧権限とメール通知を行います。  
元の「月次レポート置場」は変更しません。

## 処理スケジュール

| 日付 | 処理 |
|------|------|
| 毎月2〜3日 | 見崎さんがアップ（変更なし） |
| **毎月4日 9:00** | 前月分 PDF/Excel を店舗フォルダへコピー + 閲覧権限付与 |
| **毎月5日 9:00** | オーナーへメール通知（Drive リンク） |

例: 6月4日に **2026年5月分（202605）** を処理します。

## 前提

- Google Workspace
- Andy 店舗シート: [スプレッドシート](https://docs.google.com/spreadsheets/d/1e-QNTFdqoMK5dRIJ6Je4u7BhPRMDEFAbelzAFLyaTm8/edit)
- コピー元: `FCコンディション / 月次レポート置場`（フォルダ ID 設定済み）
- コピー先: `マイドライブ / A_もみかる本部 / B_FC加盟店`

## セットアップ手順

### 1. B_FC加盟店 のフォルダ ID を取得

1. Drive で `B_FC加盟店` を開く
2. URL の `folders/` の後ろの文字列をコピー  
   例: `https://drive.google.com/drive/folders/XXXXXXXX` → `XXXXXXXX`
3. `Config.gs` の `DEST_ROOT_FOLDER_ID` に貼り付け

### 2. Apps Script プロジェクトを作成

**方法A（推奨）: スプレッドシートに紐づける**

1. Andy 店舗シートを開く
2. **拡張機能 → Apps Script**
3. 既存コードを削除し、このフォルダ内の `.gs` / `.html` ファイルを貼り付け  
   - `Config.gs`, `Utils.gs`, `ShopMaster.gs`, `ShopKpi.gs`, `DriveCopy.gs`, `FolderMapping.gs`, `Notify.gs`, `Supervising.gs`, `Cockpit.gs`, `CockpitDashboard.html`, `Cockpit.html`, `Main.gs`
4. `appsscript.json` の内容は **プロジェクトの設定 → appsscript.json をエディタで表示** から反映

**方法B: clasp（開発者向け）**

```bash
cd fc-monthly-reports
clasp login
clasp create --type sheets --parentId 1e-QNTFdqoMK5dRIJ6Je4u7BhPRMDEFAbelzAFLyaTm8
clasp push
```

### 3. 初回承認

1. Apps Script で `testDryRunCopy` を実行
2. 権限の承認（Drive / スプレッドシート / メール送信）
3. **実行するアカウント**は、次のすべてにアクセスできる本部アカウントにする  
   - 月次レポート置場（閲覧）
   - B_FC加盟店（編集）
   - Andy シート（閲覧）
   - メール送信（`honten@momikaru.com` 等）

### 4. ドライラン → 本番

1. スプレッドシートを再読み込み → メニュー **FC月次レポート → ドライラン**
2. **配信ログ** タブで結果確認
3. 未マッチがあれば **店舗マッピング** タブに追記（例）

   | ファイル名に含まれる文字列 | kintoneShopName（Driveフォルダ名） | メモ |
   |---------------------------|-----------------------------------|------|
   | プレミアムもみかる草薙店 | 草薙店 | |
   | プレミア草薙店 | 草薙店 | |
   | SALONdeMOMIKARU呉服町店 | （実フォルダ名） | スペースなし表記 |
4. **初回バックフィル（2026/1〜）** で過去分コピー（メールは送らない）
5. **月次トリガー登録** で自動化開始

## 自動作成されるシートタブ

| タブ | 用途 |
|------|------|
| `配信ログ` | コピー・権限・通知の履歴 |
| `店舗マッピング` | ファイル名の表記ゆれ（必要時のみ） |
| `店舗フォルダマッピング` | kintoneShopName → Driveフォルダ名 / FC・直営 |

`shop` タブは **触らない**（Andy 連携のまま）。

## コピー先フォルダ構成

```
B_FC加盟店/地域/都道府県/浦添店/
  ├── 月次レポート/
  │     └── 2026/
  │           └── 05月/
  │                 ├── 月次レポート もみかる浦添店2026年05月.pdf
  │                 └── 月次レポート もみかる浦添店2026年05月.xlsx
  └── 顧客分析/
        └── 2026/
              └── 05月/
                    └── 顧客分析 もみかる浦添店2026年05月分.pdf
```

## ルール

- `全店舗` を含むファイルはスキップ
- 顧客分析は **PDF のみ** コピー（月次は PDF + Excel）
- `shop.endDate` 過去の閉店店舗は対象外
- 同一ファイル名が既にあれば再コピーしない
- オーナーには店舗フォルダの **閲覧者** 権限を付与

| 関数 | 用途 |
|------|------|
| `manualCopyForYm('202605')` | 特定月をコピー |
| `manualNotifyForYm('202605')` | 特定月を通知 |
| `runBackfillCopyFrom2026()` | 2026/1〜前月まで一括コピー |

| 症状 | 対処 |
|------|------|

# フェーズ2以降 — 全体設計（確定方針）

## 目的

月次レポートのコピー・配信に加え、**スーパーバイジング**と**蓄積データ**を軸に、本部の必須アプリを構築する。

```
見崎さんアップ → コピー → KPI蓄積 → コックピットで承認
    → 5日配信（Chat/LINE + コメント）
    → Chatナレッジ同期 → 既存BOTでオーナーがLINE質問可能
```

## 処理スケジュール（目標）

| 日付 | 処理 |
|------|------|
| 毎月2〜3日 | 見崎さんが月次レポート・顧客分析をアップ |
| **毎月4日 9:00** | 前月分を店舗フォルダへコピー（通知はまだ出さない） |
| **毎月5日 9:00** | ① 顧客分析+月次レポート PDF が両方揃った店舗のみ **1回** 配信<br>② 承認済みスーパーバイジングを同梱<br>③ **Chatナレッジを同期**（既存BOT用） |

※ 4日コピー時の Drive 共有通知は抑止予定（権限付与は通知直前に移動）。

## スーパーバイジングの設計（レポート読解ベース）

岩出店 2026年3月レポートをモデルに確定。AIは **レポート記載の数字のみ** を根拠にする。

### レポートから使う主要指標

| 区分 | 指標 |
|------|------|
| 基本 | 実売上、来客数、客単価、損益分岐点（PDF冒頭記載） |
| 稼働 | **ベッド稼働率**、**ベッド稼働台数**、**取りこぼし件数** |
| 集客 | 新規来客数、新規リピート比率、顧客定着率（60日） |
| 構造 | 曜日別・時間帯別・年代×性別（**集計のみ**） |
| コスト | 外注費、外注比率（必要時） |

### 稼働率の扱い

レポート定義そのまま使用（自前のシフト時間管理はしない）。

```
ベッド稼働率 ＝ 全施術者の月間施術時間合計
            ÷（ベッド数 × 営業時間（分）× 当月日数）× 100
```

+5％ポイントの試算例（岩出店 202603）:

- 稼働率 20％ → +5％ポイント ≒ 約174時間/月の施術時間増
- 売上増（比例試算）≒ 実売上 ×（5 ÷ 現在稼働率）※「試算」と明記

### 優先テーマ判定

| シグナル | テーマ |
|----------|--------|
| 稼働率低 + 取りこぼし少 | 集客 |
| 稼働率低 + 取りこぼし多 | **両方**（集客＋受け入れ時間） |
| 稼働率高 + 取りこぼし多 | 求人・シフト増 |
| 新規比率・定着率低 | 集客・リピート |
| 特定曜日のみ弱い | 曜日別集客を具体化 |

### 本文構成（確定）

1. 【今月のコンディション】
2. 【数字から見える良い点】
3. 【数字から見える課題】
4. 【稼働と収益のポテンシャル】（該当店のみ・試算明記）
5. 【今月の優先テーマ】集客 / 求人 / 両方
6. 【施策のご提案】施策ナレッジから1〜2件
7. 【来月に向けたアクション】
8. 【本部より】（任意・人手追記）

トーン: **スーパーバイザー**（上でも下でもない）。店舗ごとに個別送信。

## Chatナレッジ / 既存BOT連携

### 方針

- **新BOTは作らない** — 既存「もみかる本部サポート連携」GAS に検索・回答を追加
- オーナーは **LINE から質問** → 既存経路で自動回答
- **ナレッジ更新タイミング: 毎月5日**（配信と同時）

### ナレッジに載せる / 載せない

| 載せる | 載せない |
|--------|----------|
| 店舗×月のKPI（集計） | 顧客の氏名・メール・電話 |
| 承認済みスーパーバイジング | 未承認AI下書き |
| 施策提案・本部コメント | **地域平均・他店比較**（オーナー向け） |
| 年代×性別など**集計** | 他店舗の数値・店名（オーナー権限外） |

### 権限

```
lineUserId → line_link → userm → userxshop（userStop=0）
  → オーナー: 紐づく店舗のみ回答
  → 本部（adminLevel 32/41 等）: 全店検索可
```

複数店舗オーナーは店舗ごとに個別データ・個別回答。

### オーナーがLINEで聞ける例

- 「3月の稼働率は？」「取りこぼしは何件？」
- 「本部が言っていた来月のアクションは？」

### 答えない例

- 他店の売上・稼働率
- 地域平均
- 個人を特定できる顧客情報

## コックピット UI 方針

### 技術選定

| 項目 | 方針 |
|------|------|
| 基盤 | **Google Apps Script HtmlService**（追加サーバー不要） |
| 認証 | スプレッドシート／Webアプリ実行 = **本部 Workspace アカウント** |
| オーナー向けUI | **作らない**（オーナーは LINE + 既存BOT） |

本部専用ツールとして Andy シートに紐づける。

### 開き方（2通り）

| 方法 | 用途 |
|------|------|
| **メニュー → コックピットを開く** | スプレッドシート上のモーダル（1280×860）※**v1・現在** |
| **Webアプリとしてデプロイ**（`doGet`） | ブラウザのブックマークURLで全画面作業 ※**本部の常用推奨** |

Webアプリデプロイ手順:

1. Apps Script → **デプロイ → 新しいデプロイ**
2. 種類: **ウェブアプリ**
3. 実行ユーザー: **自分**、アクセス: **組織内**（または特定ユーザー）
4. 表示URLを本部スタッフで共有

### UI の段階的進化

#### v1（レガシー）— 単店舗エディタ

1画面で1店舗・1ヶ月を編集。テストと下書き生成に最適。メニュー「コックピット v1」または `openCockpitV1`。

```
[店舗選択] [対象月]
[PDFアップロード ×2] [Driveから読込] [AI下書き生成]
[登録ファイル一覧]  |  [スーパーバイジング本文（編集）]
                      [保存] [承認済み]
```

ファイル: `Cockpit.html`, `Cockpit.gs`, `Supervising.gs`

#### v2（現在）— 本部ダッシュボード

メニュー **FC月次レポート → コックピットを開く** で起動（`CockpitDashboard.html`）。

- 左: 店舗一覧（要対応 / 未着手 / 下書き / 承認済み、テーマ別フィルタ）
- 右: KPIカード、12ヶ月推移、PDF、スーパーバイジング編集
- `店舗月次KPI` タブに手入力するとダッシュボードに反映（自動抽出は今後）

Webアプリとして `doGet` をデプロイすると全画面で利用可能。

#### v3（予定）— ナレッジ管理

- 施策ナレッジの追加・編集画面
- 施策効果ログの確認
- 5日同期ステータス（BOTナレッジ反映済みか）

### デザイン

- 本部の業務ツールとして **シンプル・読みやすさ優先**
- 色は落ち着いたトーン（現在の `Cockpit.html` のオレンジアクセントを継続）
- スマホ対応は本部がPC中心なら v2 まで必須ではない

### v1 → v2 移行時の実装方針

- `Cockpit.html` を `CockpitDashboard.html` に拡張、またはタブ切替
- バックエンド（`Cockpit.gs`）は店舗一覧API・KPI API を追加
- v1 の店舗エディタは v2 の右ペインとして再利用（作り直し最小）
